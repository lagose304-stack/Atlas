# Sistema de pruebas de instructores

Implementación del 14 de noviembre de 2026. SQL instalado con autorización mediante `add_instructor_tests_system`; frontend disponible en local y pendiente de publicación.

## Comportamiento

- El módulo existente `/pruebas/instructores` permite crear pruebas, editar nombre/instrucciones y añadir hasta 100 preguntas de selección única, respuesta breve, completación y términos pareados. La ampliación SQL ya está instalada; el frontend sigue disponible en local y pendiente de publicación.
- Solo la cuenta inicial de Atlas y el Jefe de Microscopia actual administran el contenido. Las RPC comprueban la sesión propia y la fila de jefatura; el rol Administrador por sí solo no basta. No se modifica el esquema de roles ni las pruebas normales.
- Guardar crea o actualiza un borrador. Publicar valida que exista código y que las preguntas estén completas, y genera un snapshot público. Un borrador editado no altera las preguntas publicadas hasta publicar otra vez. Se puede retirar la publicación y volver a borrador.
- La vista principal muestra las pruebas guardadas en un listado con su estado y acciones por fila: Editar, Publicar o Pasar a borrador. Si una prueba publicada tiene cambios guardados, ofrece también Publicar cambios. El editor se abre aparte dentro del módulo; al guardar vuelve al listado. Volver sin guardar pide confirmar el descarte. Las acciones de publicación usan la revisión de la fila y actualizan solo esa prueba. No requieren otro SQL ni modificaciones de las pruebas existentes.
- `Evaluaciones.tsx` incluye `PublicInstructorTests.tsx` después de todas las secciones de parciales. El catálogo solo devuelve pruebas publicadas, título, instrucciones y cantidad de preguntas; nunca códigos ni preguntas. Respeta el ocultamiento de evaluaciones en la interfaz de mantenimiento.
- `/evaluaciones/instructores/:pruebaId` solicita un código ASCII de exactamente seis dígitos. Se conserva como texto para admitir ceros iniciales. El editor puede sustituirlo, pero no recuperar el código anterior: se guarda únicamente su hash bcrypt mediante pgcrypto.
- Las preguntas se entregan tras validar el código en servidor, sin la respuesta correcta. Un token opaco, guardado solo en memoria en el navegador y como hash en servidor, permite calificar durante dos horas. Una publicación nueva, retirar la publicación o cambiar el código invalida accesos anteriores. Recargar vuelve a pedir código.
- El nuevo código entra en vigor al guardar, incluso si las preguntas públicas siguen en su versión anterior. La interfaz lo explica antes del guardado.
- En el editor y en la pantalla de acceso, el campo oculta el código. El botón con el ojo solo lo revela mientras se mantiene presionado con ratón, toque o Espacio/Enter; al soltar, salir, cancelar el contacto, perder foco o cambiar de pestaña vuelve a ocultarlo. No recupera el código almacenado; solo muestra lo que se está introduciendo. Verificado con pruebas de interacción y Chromium con eventos táctiles simulados; no requiere SQL.
- El servidor califica una sola entrega por token y conserva el resultado para reintentos de red. Se muestra cantidad de preguntas correctas y porcentaje. No hay todavía identificación nominal de instructores, historial administrativo de resultados ni imágenes.
- Tras cinco códigos incorrectos se bloquean los intentos durante quince minutos por prueba y origen. Se usa un hash del primer `x-forwarded-for`; sin cabecera existe un límite compartido conservador. Antes de producción debe comprobarse que la cabecera procede del proxy de confianza. No equivale a un límite distribuido entre orígenes.

Cada pregunta tiene un selector de formato. `src/types/instructorQuestions.ts` define las variantes privadas/públicas y las respuestas del participante. `InstructorQuestionEditor.tsx` presenta la configuración y `InstructorQuestionResponse.tsx`, los campos de respuesta. Cambiar de formato conserva el ID y el enunciado y pide confirmar si reemplazará respuestas configuradas.

| Formato | Configuración | Respuesta del participante |
| --- | --- | --- |
| Selección única | 2–8 opciones y una correcta. | ID de la opción. |
| Respuesta breve | 1–20 variantes aceptadas, una por línea. | Texto breve, hasta 1000 caracteres. |
| Completación | 1–12 huecos, cada marcador `{{1}}`, `{{2}}`, etc. una vez en el enunciado, con variantes por hueco. | Objeto por ID de hueco. |
| Términos pareados | 2–12 parejas con términos y opciones únicos; IDs independientes. | Objeto de asociaciones por ID, sin reutilizar opciones. |

Las preguntas históricas sin `type` se interpretan como selección única sin reescribir JSON, IDs, códigos ni snapshots. Cada pregunta vale lo mismo: una completación o pareado cuenta como correcta únicamente si todos sus huecos o asociaciones son correctos. La respuesta breve y los huecos comparan variantes explícitas, sin aproximaciones, ignorando mayúsculas, tildes vocálicas y espacios sobrantes; Unicode descompuesto se normaliza y la ñ se conserva distinta de n.

`database/extend_instructor_question_formats.sql` sustituye únicamente `atlas_validate_instructor_content`, `atlas_unlock_instructor_test` y `atlas_grade_instructor_test`, conservando firmas y privilegios. Añade dos auxiliares privados para normalización y proyección pública. No modifica tablas ni filas. La proyección solo incluye campos permitidos: no envía respuestas aceptadas, claves de selección ni el mapa privado de parejas. Las opciones pareadas se mezclan al obtener el acceso, conservando el orden de términos y preguntas.

| Tabla | Contenido |
| --- | --- |

## Pregunta inversa: senalar en imagen y revision manual

El quinto formato `image_point` presenta una foto sin marcas del catalogo ni pistas del editor. Su respuesta es exclusivamente un objeto `{x,y}` con coordenadas finitas entre 0 y 1. El autor selecciona o sube imagen y escribe instrucciones; no configura respuesta correcta automatica. Al reemplazar la imagen se descartan sus marcas. El modo reducido reutiliza transformaciones y colocacion del editor habitual, ofrece solo un punto reposicionable y eliminable, mano y zoom. Muestra las instrucciones y permite guardar o cancelar sin perder una respuesta anterior. No modifica las herramientas de los consumidores anteriores.

`database/add_instructor_point_questions.sql` esta preparado localmente y requiere aplicar antes imagenes y anotaciones. Crea `instructor_test_submissions`, privada mediante RLS y revocacion de acceso directo, con indice por prueba y fecha. Guarda snapshot publico de preguntas, URL y geometria de imagen, respuestas originales, revision publicada, puntaje automatico y decisiones manuales. La entrega se inserta en la misma transaccion que el resultado idempotente y no depende de la vida del acceso temporal. Un reintento no cambia respuestas ni duplica entregas. No copia el archivo R2: conserva la URL y se mantiene la regla existente de no eliminar imagenes compartidas. La fotografia podria cambiar si otro flujo reemplaza el objeto de esa URL.

Las nuevas RPC de listado, detalle y revision verifican la sesion Atlas con la autoridad actual de microscopia. Las listas estan paginadas a 50 entregas. El detalle no expone hashes/tokens. La revision solo admite booleanos para los incisos `image_point` de ese snapshot y exige revision coincidente; una decision incorrecta aporta cero y una correcta un punto, como los formatos actuales. El resultado permanece sin porcentaje final mientras falte una decision manual. La pantalla publica indica entrega pendiente, muestra una referencia y permite consultar la revision mientras conserve el acceso vigente. La revision administrativa permanece disponible aunque expire o se limpie el acceso. Cancelar no escribe y un fallo conserva la entrega y decisiones locales. Tras exito se cierra solo el detalle eliminado y se recarga la ventana paginada para no saltar filas por el desplazamiento. Si falla solo la recarga, se informa que el borrado si se completo. No se implementa borrado masivo implicito.

`database/delete_instructor_submissions.sql` crea una unica RPC SECURITY DEFINER con search_path fijo y comprobacion `atlas_require_instructor_manager`. Exige prueba, ID y revision vigente para evitar eliminar sobre una revision cambiada; reintentar una eliminacion ya completada es idempotente. Bloquea la prueba con FOR UPDATE para serializar con inicio/recuperacion/guardado/entrega y despues bloquea la entrega. Elimina accesos por hash de entrega o enlace a su progreso, progreso por submission_id exacto y fila de entrega. No borra por nombre/cuenta de forma general ni afecta intentos o entregas de otra version. Las otras respuestas, preguntas, configuracion, publicacion y objetos R2 se conservan. Al retirar el progreso finalizado se libera la cuenta para iniciar otra vez esa misma version si el horario actual lo permite.

Instalar el SQL no ejecuta borrados. Requiere la estructura de recuperacion por cuenta existente. Solo los gestores actuales de microscopia pueden ejecutar el endpoint; anon/authenticated tienen EXECUTE para transportar la sesion Atlas y no acceso directo a tablas. La plantilla de desactivacion revoca ese endpoint, conservando datos. No hay recuperacion por SQL de filas ya borradas: exportar respuestas/revisiones que deban conservarse antes de eliminar. Antes de instalar en remoto, revisar dependencia, ausencia/conflictos del nombre de funcion y alcance; cada uso del boton solicita confirmacion concreta. No se instalo ni se borro ninguna entrega de produccion en esta tarea.
